Q1: Checking that a user is who they claim to be is

Multiple Choice
**Explanation:** RFC 4949 defines authentication as verifying a claim that an entity or resource has a particular attribute value. For a login, that attribute is commonly the user's claimed identity. **Options:** - A (correct): Authentication is the verification step applied to the claimed identity. - B (incorrect): Authorization grants or evaluates approval to access a resource after relevant attributes are known. - C (incorrect): Identification presents the claimed value, such as a user identifier; it does not by itself verify the claim.

Q2: Deciding whether an authenticated user may delete a record is

Multiple Choice
**Explanation:** Authorization is an approval, or the process of granting approval, for an entity to access a resource. The requested operation can be evaluated only after the system has an identity and the applicable policy. **Options:** - A (incorrect): Authentication verifies an attribute claim; it does not grant deletion permission. - B (correct): Deciding whether this entity may perform this action is an authorization decision. - C (incorrect): Accounting records or measures activity and is not the permission decision itself.

Q3: Protecting data so outsiders cannot read it is most closely

Multiple Choice
**Explanation:** Confidentiality concerns keeping information from being disclosed to unauthorized entities. It is distinct from preserving correctness and from keeping a service usable. **Options:** - A (incorrect): Availability concerns whether an authorized entity can access or use a resource when needed. - B (incorrect): Integrity concerns unauthorized modification or destruction of data. - C (correct): Preventing unauthorized reading is a confidentiality objective.

Q4: Detecting that a message was modified in transit is most closely

Multiple Choice
**Explanation:** Data integrity is the property that data has not been changed or destroyed in an unauthorized manner. An integrity mechanism can let a receiver detect modification during transit. **Options:** - A (incorrect): Confidentiality limits disclosure but does not by itself establish that received data is unchanged. - B (correct): Detecting unauthorized modification is an integrity function. - C (incorrect): Availability concerns access or operation on demand, not whether a message was altered.

Q5: A random or non-repeating value included in a protocol exchange to help detect replay is called a

Multiple Choice
**Explanation:** RFC 4949 defines a nonce as a random or non-repeating value included in protocol data, usually to provide liveness and protect against replay. Its freshness, rather than secrecy, is the key property in this use. **Options:** - A (correct): A nonce supplies the random or non-repeating value described in the stem. - B (incorrect): A credential carries evidence or attributes used in security decisions; it is not inherently fresh. - C (incorrect): A checksum can detect some data changes but does not inherently make a protocol exchange non-repeating.

Q6: What attack maliciously repeats a valid data transmission? (two words)

Short Text
**Explanation:** **Correct:** **replay attack**. The glossary defines it as malicious or fraudulent repetition of a valid data transmission, either by its originator or by an interceptor who retransmits it. Freshness mechanisms such as nonces can help a receiver reject previously used protocol data.
