Q4: According to RFC 7807, what should the status member contain when it is present

Multiple Choice
**Explanation:** **Terms:** status member **Correct (A):** The status member, when present, is the HTTP status code generated by the origin server for this occurrence **Options:** - A (correct): It duplicates the origin response status as a convenience for clients. - B (incorrect): status is numeric in the standard members - C (incorrect): status describes this occurrence; it does not predict a later response. **Related:** An intermediary can change the response status in transit, so a generic client should use the actual HTTP response status rather than treat the payload member as a separate authority.

Q5: Which member is a short human readable summary of the problem (one word)

Short Text
**Explanation:** **Terms:** title, detail **Correct:** title is the short, human-readable summary of the problem type. It should not change from occurrence to occurrence except for localization. **Related:** detail is a human-readable explanation specific to this occurrence, so it may contain facts that differ between requests.
