RFC 6265 Paper Story

クッキーのおふだと村の約束

HTTP Cookie は、サーバがブラウザに状態を預け、次のリクエストで条件に合うものだけを返してもらう仕組みです。このページでは、RFC 6265 の要点を短い紙芝居アニメとして確認します。

State Set-Cookie と Cookie の向きを区別します。
Scope Domain と Path は、どこへ返すかを絞ります。
Guard Secure と HttpOnly は、送信や露出を制限します。
再生用紙芝居 1 / 6: 村役場がおふだを渡す
Scene 1

村役場が、おふだを旅人に預ける。

サーバはレスポンスで Set-Cookie を送り、ブラウザに名前と値、それに属性を保存させます。

仕様の対応: Set-Cookie はサーバからユーザーエージェントへ向かうレスポンスヘッダーです。
Scene 2

次の訪問で、旅人はおふだを見せる。

ブラウザは、リクエスト先に合う保存済み Cookie を選び、Cookie ヘッダーとしてサーバへ返します。

仕様の対応: Cookie はユーザーエージェントからサーバへ向かうリクエストヘッダーです。
Scene 3

おふだには、使える村と道が書かれている。

Domain はどのホストへ返すか、Path はどのパスへ返すかを絞ります。何でも全ての場所へ送る仕組みではありません。

仕様の対応: 属性が示すスコープにより、ユーザーエージェントは後続リクエストで返す Cookie を選びます。
Scene 4

大事なおふだは、安全な橋だけを通る。

Secure が付いた Cookie は、ユーザーエージェントが安全と判断する通信でだけ送信されます。通常は HTTPS が該当します。

注意: Secure は送信条件を制限しますが、Cookie の値を暗号化したり、全ての改ざんを防いだりする印ではありません。
Scene 5

いたずら狐には、おふだを見せない。

HttpOnly は、通常のクライアント側スクリプトなど、HTTP ではない API から Cookie を見えにくくします。

注意: HttpOnly はスクリプト注入そのものを直す仕組みではありません。Cookie への露出を減らすための属性です。
Scene 6

期限が来れば、おふだは役目を終える。

Expires と Max-Age は Cookie の寿命に関係します。同じ名前、ドメイン、パスの Cookie が来れば、古いものは置き換えられます。

まとめ: Cookie は便利な状態管理ですが、属性の意味と限界を理解して使う必要があります。

物語と RFC 6265 の対応

物語上の道具を、実際のHTTP Cookieの概念に戻します。

初心者向け対応表
物語の要素 RFC 6265 の概念 理解すべき点
村役場がおふだを渡す Set-Cookie サーバがレスポンスで、ブラウザに保存してほしい名前と値、属性を渡す。
旅人がおふだを見せる Cookie ブラウザが後続リクエストで、条件に合う保存済み Cookie をサーバへ返す。
村と道の約束 Domain / Path Cookie を返すホストとパスの範囲を絞る。認可そのものではない。
安全な橋 Secure 安全と判断される通信でだけ送る。値の暗号化や完全な改ざん防止ではない。
いたずら狐から隠す HttpOnly HTTPではないAPIからの露出を減らす。スクリプト注入自体を防ぐ機能ではない。
期限が来たおふだ Expires / Max-Age Cookie の寿命を扱う。Max-Age がある場合は Expires より優先される。
