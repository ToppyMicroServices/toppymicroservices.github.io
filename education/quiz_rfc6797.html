Q1: Which header enables HSTS policy in browsers

Multiple Choice
**Explanation:** A conforming user agent processes the `Strict-Transport-Security` response field only when it arrives over secure transport without underlying security errors. The field carries the required `max-age` directive and may carry `includeSubDomains`. **Options:** - A (incorrect): `Transport-Security` is not the response-field name defined by RFC 6797. - B (correct): `Strict-Transport-Security` is the field that conveys an HSTS policy. - C (incorrect): `Secure-Only` is not the HSTS response-field name.

Q2: Which directives are defined for Strict-Transport-Security by RFC 6797? (select all)

Multi-Select
**Explanation:** RFC 6797 defines one required directive, `max-age`, and one optional directive, `includeSubDomains`. User agents must ignore unrecognized directives while processing an otherwise valid field. **Options:** - A (correct): `max-age` gives the policy lifetime in seconds and is required by the field grammar. - B (correct): `includeSubDomains` optionally extends the policy to subdomains. - C (incorrect): `preload` is not a directive defined by RFC 6797; browser preload enrollment is a separate operational mechanism. - D (incorrect): `allowInsecure` is not an RFC 6797 directive and would conflict with the policy's purpose.

Q3: A limitation of HSTS is that it cannot fully protect

Multiple Choice
**Explanation:** An HSTS policy learned through an HTTP response over secure transport cannot protect an earlier, insecure first contact. An active attacker can interfere before the user agent has recorded the host as a Known HSTS Host. **Options:** - A (incorrect): Once an unexpired policy is cached, the user agent rewrites insecure loads and enforces secure transport for that host. - B (incorrect): A learned policy with `includeSubDomains` extends enforcement to matching subdomains. - C (correct): The bootstrap request remains exposed when the user agent has no prior policy. A preloaded Known HSTS Host list can mitigate this bootstrap gap, but RFC 6797 does not define a `preload` header directive.

Q4: What is the unit of max-age in HSTS

Multiple Choice
**Explanation:** The `max-age` value uses the `delta-seconds` grammar: one or more decimal digits representing seconds after receipt of the field. Repeated valid fields refresh the policy's expiry relative to their receipt time. **Options:** - A (correct): Seconds are the unit required by the RFC 6797 grammar. - B (incorrect): A value intended as minutes must first be converted to seconds. - C (incorrect): A value intended as days must also be converted to seconds.

Q5: What directive applies the policy to all subdomains (one token)

Short Text
**Explanation:** **Correct:** **includeSubDomains**. This optional, valueless directive extends the HSTS policy from the issuing host to its subdomains. Before asserting it, a deployment must account for subdomains that still depend on insecure HTTP services because those services can become unreachable to conforming user agents.

Q6: A safe rollout strategy for HSTS often starts with

Multiple Choice
**Explanation:** A user agent caches HSTS policy until the `max-age` expiry and refreshes that expiry when it receives a later valid field. Starting with a short lifetime and observing the deployment is therefore a conservative rollout practice, not a normative sequence required by RFC 6797. **Options:** - A (incorrect): A long lifetime plus `includeSubDomains` widens both the duration and scope of any configuration error. - B (correct): A short initial lifetime limits persistence while monitoring reveals certificate, redirect, and subdomain problems. - C (incorrect): A conforming user agent ignores an STS field received over insecure transport.
