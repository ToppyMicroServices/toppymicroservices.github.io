Q1: The main purpose of TLS extensions is to

Multiple Choice
**Explanation:** RFC 6066 uses the TLS extension framework to add capabilities such as server-name indication, fragment-length negotiation, and certificate-status requests. These extensions are designed so supporting endpoints can still communicate with peers that do not support them. **Options:** - A (incorrect): Some extensions influence certificate handling, but the framework does not move validation into the application protocol. - B (correct): Backward-compatible capability negotiation is the shared design purpose. - C (incorrect): Optional extensions are designed to coexist with peers that do not support every new capability.

Q2: Which RFC 6066 extension lets a client ask the server to send certificate-status information such as an OCSP response during the handshake?

Multiple Choice
**Explanation:** The `status_request` extension negotiates delivery of server-certificate status information in the TLS handshake. RFC 6066 defines the corresponding `CertificateStatus` handshake message and an OCSP response form. **Options:** - A (incorrect): `trusted_ca_keys` indicates CA root keys possessed by the client. - B (correct): `status_request` is the extension for requesting certificate-status information. - C (incorrect): `client_certificate_url` lets a client offer URLs in place of sending its certificate chain directly.

Q3: Which value follows RFC 6066's encoding rules for server_name HostName?

Multiple Choice
**Explanation:** RFC 6066 defines `HostName` as the fully qualified DNS hostname understood by the client, encoded as an ASCII byte string without a trailing dot. Internationalized names use A-labels, and literal IPv4 and IPv6 addresses are not permitted in this field. **Options:** - A (incorrect): Literal IP addresses are expressly excluded from `HostName`. - B (correct): It satisfies both the DNS-name and encoding constraints. - C (incorrect): The field is ASCII without a trailing dot, not a raw UTF-8 name ending in one.

Q4: A well designed extension negotiation should (select all)

Multi-Select
**Explanation:** Extension design needs explicit compatibility and failure semantics. RFC 6066 demonstrates backward-compatible optional features and provides feature-specific security considerations; it does not justify assuming every new extension is harmless. **Options:** - A (correct): Defined handling of unsupported extensions preserves communication with older peers where the extension is optional. - B (correct): Peers need to know whether lack of support permits fallback or requires handshake failure. - C (correct): New inputs and behavior create security properties and failure modes that must be analyzed. - D (incorrect): An extension can add attack surface, privacy exposure, or downgrade risk.

Q5: A TLS server hosts two names on one IP and uses a different certificate for each. Before any HTTP request arrives, which ClientHello information lets it select the certificate

Multiple Choice
**Explanation:** **Terms:** SNI carries the requested DNS hostname in the ClientHello **server_name** extension, before the server sends its certificate. **Correct (B):** RFC 6066 allows a server to use the server_name information to guide selection of the certificate returned to the client. **Options:** - A (incorrect): ALPN identifies the application protocol, such as HTTP/2, rather than the requested hostname. - B (correct): The SNI server_name distinguishes the virtual host early enough for certificate selection. - C (incorrect): A session ticket carries resumption state; it is not the hostname selector for a new virtual-host connection. **Related:** This is why name-based HTTPS virtual hosting can serve different certificates from one IP address.

Q6: Which RFC 6066 extension negotiates a smaller maximum TLS plaintext fragment length? (one token)

Short Text
**Explanation:** **Correct:** **max_fragment_length**. Constrained clients can offer this extension with one of the sizes defined by RFC 6066. A server accepts by echoing the same requested value; a different or unsupported value causes an `illegal_parameter` failure under the specified rules.
