Q1: A URL with scheme https implies

Multiple Choice
**Explanation:** RFC 2818 defines HTTPS as HTTP carried over TLS. When the server hostname is known from the URI, the client generally checks it against the identity presented in the server certificate. **Options:** - A (incorrect): The scheme describes this resource access; it does not permanently prohibit the same host from serving HTTP. - B (correct): It combines HTTP over TLS with the endpoint-identification expectations specified for HTTPS. - C (incorrect): Base64 is an encoding and provides neither TLS encryption nor server authentication.

Q2: The default port for https URLs is

Multiple Choice
**Explanation:** RFC 2818 records **443** as the default TCP port for HTTP over TLS. A URL can still contain another explicit port; default does not mean mandatory for every deployment. **Options:** - A (correct): `443` is the registered default for an HTTPS URL with no explicit port. - B (incorrect): `80` is the conventional default for plain HTTP. - C (incorrect): `22` is commonly associated with SSH, not HTTPS.

Q3: TLS provides which properties for HTTP messages (select all)

Multi-Select
**Explanation:** TLS gives HTTP a protected channel and supports endpoint authentication. It does not determine application identities, roles, or permissions after that channel has been established. **Options:** - A (correct): Encryption protects message confidentiality against passive network observation. - B (correct): TLS record protection detects unauthorized modification in transit. - C (correct): Certificate validation and hostname checking support server authentication. - D (incorrect): Application authorization remains a responsibility of the service using HTTPS.

Q4: Your app builds a destination URL from user input and may attach an access token. Which validation policy best prevents an HTTP downgrade?

Multiple Choice
**Explanation:** Scheme validation must happen before a sensitive request is sent. A trusted host alone is insufficient because an `http` URL would place the first request, including any attached token, outside TLS protection. **Options:** - A (incorrect): A redirect occurs only after the initial insecure request has already left the client. - B (incorrect): Host validation limits destinations but does not prevent plaintext transport to an allowed host. - C (correct): Checking both destination and scheme before adding the token closes the downgrade path in the scenario.

Q5: A correct statement about the https scheme is

Multiple Choice
**Explanation:** RFC 2818 distinguishes HTTP over TLS by using the `https` protocol identifier in place of `http`. The scheme carries transport and default-port meaning; it does not select an HTTP authentication scheme or impose a universal redirect policy. **Options:** - A (correct): `https` and `http` are distinct URI schemes with different access semantics. - B (incorrect): Basic authentication is an independent HTTP authentication mechanism and is not required by HTTPS. - C (incorrect): Redirect handling is not categorically prohibited by the `https` scheme.

Q6: When an HTTPS URI uses an IP address, which subjectAltName type must exactly match it? (one token)

Short Text
**Explanation:** **Correct:** **iPAddress**. RFC 2818 requires an `iPAddress` subjectAltName when the URI identifies the server by an IP address, and that value must exactly match the URI's address. A `dNSName` entry is used for DNS hostnames instead.
