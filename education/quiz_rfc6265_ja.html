Q1: browserへcookieを設定するresponse headerはどれ

Multiple Choice
**Explanation:** `Set-Cookie` は, cookieを保存または更新するようuser agentへ指示するresponse headerです. `Cookie` は反対向きで, 保存済みcookieのうちrequestに適用できるものをuser agentがserverへ返すときに使います. A: `Cookie` は保存済みcookieをserverへ返すrequest headerです. B: `Set-Cookie` はcookie stateの作成または更新に使うresponse headerです. C: `Accept-Cookie` はRFC 6265で定義されたheaderではありません.

Q2: cookie attributeとして一般的なものはどれ (複数選択)

Multi-Select
**Explanation:** RFC 6265は, cookieのtransport, APIへの露出, path scope, lifetimeを制御するattributeを定義しています. HTTP cache directiveは別のheader fieldに属し, `Set-Cookie`内のcookie attributeにはなりません. A: `Secure` はuser agentがsecureと判断するprotocolに送信を制限します. B: `HttpOnly` は通常のscript accessなど, non-HTTP APIからcookieを除外します. C: `Path` はcookieを適用できるrequest pathを制限します. D: `Max-Age` はcookieのlifetimeを秒で指定し, `Expires`より優先されます. E: `Cache-Control` はHTTP cachingを制御するheaderで, `Set-Cookie` attributeではありません.

Q3: HttpOnlyの主な効果はどれ

Multiple Choice
**Explanation:** `HttpOnly` はcookieのhttp-only flagを設定します. conformingなuser agentはnon-HTTP API用のcookie stringを作るときにそのcookieを除外するため, 通常のclient-side scriptからのaccessを減らせます. valueを暗号化したり, script injection自体を解消したりする機能ではありません. A: non-HTTP APIからcookieを隠すことがhttp-only flagの役割です. B: `HttpOnly` は保存時にも送信時にもcookieを暗号化しません. C: request pathのscopeは`Path` attributeが制御します.

Q4: Secure attributeの意味として正しいのはどれ

Multiple Choice
**Explanation:** `Secure` はcookieのsecure-only flagを設定します. user agentはrequest URIがsecureと判断するprotocol, 通常はHTTPSを使う場合にだけそのcookieを送ります. valueへの署名, 変更不能化, expiryの指定ではありません. `Secure`の保護範囲には限界があります. RFC 6265は, active network attackerがinsecure channelからSecure cookieを上書きできる点も述べています. A: RFC 6265は`Secure` cookieをbrowserが署名する処理を定義していません. B: 削除とexpiryはcookieの置換, `Max-Age`, `Expires`, storage ruleが制御します. C: secure protocolへの送信制限がsecure-only flagの役割です.

Q5: serverがDomain attributeなしでcookieを設定した. RFC 6265ではどのscopeになる?

Multiple Choice
**Explanation:** RFC 6265 Section 5.3 step 6は`Domain`がない場合にhost-only flagを設定し, canonicalizeしたrequest hostをcookieのdomainにします. Section 5.4は後続requestのhostがそのdomainと同一の場合だけcookieを返します. 固定されたscope ruleの適用問題なのでL2であり, L3の設計reviewではありません. A: subdomainへのdomain-matchは, 有効な`Domain` attributeがあるcookieに関係します. B: attributeの省略によってorigin serverのhostに結び付くhost-only cookieになります. C: `Path` matchは追加条件であり, 無関係なhostへcookieを許可しません.

Q6: cookieをserverへ返すrequest header名は何 (1語)

Short Text
**Explanation:** user agentはdomain, path, secure-only, http-onlyなどの条件がrequest contextに合う保存済みcookieから, `Cookie` request headerを組み立てます. `Set-Cookie`はresponse側のfieldなので, この問いの名前ではありません.
