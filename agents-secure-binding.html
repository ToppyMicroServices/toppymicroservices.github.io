Technical note

Agents Secure Binding

Bind delegated Agent identity to the live session.

ASB is an experimental verifier-side acceptance profile. It checks that the grant, holder-of-key proof, accepted TLS or exported-authenticator session, and local policy refer to the same interaction.

Read the SSOT GitHub repository

docs/SSOT.md is the public source of truth. If this overview differs, the SSOT takes precedence.

Problem

Valid evidence can still describe the wrong interaction

A grant and session proof can each verify while referring to different Agents, tasks, or sessions.

Session binding

Bind the grant to the accepted session

A replayed or substituted proof fails even when its signature is valid.

Happy path

grant and live session match
1. Authority Signs the Agent's Identity Grant. Identity Grant
2. Agent Opens the accepted session. live session
3. Agent → Verifier Binds the exact grant to that session. Session Binding Statement
Result: ACCEPT

Attack path

valid signature, wrong session
1. Attacker Replays a binding or substitutes a grant. old / wrong grant
2. Attacker → Verifier Presents the proof in another session or context. mismatched context
3. Verifier Finds a grant, key, session, or policy mismatch. local policy
Result: REJECT

Verifier checklist

Accept only when every check passes

  • ✓The grant signature is valid, and the grant authorizes the Agent key.
  • ✓grant_hash and the binding match the exact grant and current session.
  • ✓Freshness and replay checks pass, and any required attestation is valid.
  • ✓The bound values match local policy.

Peer metadata may be evidence, but it does not define the verifier's policy.

Approach

Separate the roles, then check that they agree

The authority key signs the Identity Grant. The authorized Agent key binds that exact grant to the accepted session. The endpoint key authenticates the accepted TLS or exported-authenticator endpoint.

Two signed objects

The Identity Grant states the delegated authority and scope. The Session Binding Statement binds that grant to the accepted session.

Verification order

Authenticate both objects, check the session and local policy, then record replay state. If a check fails, the identity is not accepted.

Implementation

What exists today

The repository contains verifier code and tests covering rejection of invalid or mismatched input before the application receives an accepted Agent identity.

  • Token formats: JWT/JWS and CWT/COSE verifier coverage.
  • Verifier safety: local-policy checks, replay handling, and cache safety for caller-dependent results.
  • Security tests: negative tests for replay, binding and key mismatches, grant substitution, and cache misuse.

Status and sources

Proposal, not a standard

This is a proposal and implementation experiment, not standards-body consensus or AGTP/A2A core protocol text. It defines a verifier-side acceptance gate, not a full protocol stack. Gateway-routed deployments need a separate binding profile.
