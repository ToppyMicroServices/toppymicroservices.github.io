# Beads workflow

This repository uses a remote-backed Dolt database as the live Beads issue
store. Beads 1.1.0 does not provide `bd sync`.

## Start work

```bash
bd version
bd hooks install --shared
bd dolt pull
bd ready
bd update <id> --claim
```

If `bd` reports pending schema migrations, do not migrate independently. One
designated clone must migrate and push the schema; all other clones use
`bd bootstrap` after the migration is published.

## Publish issue changes

```bash
bd vc status
bd dolt commit -m "<issue summary>"
bd dolt push
python3 scripts/export_beads_snapshot.py
git add .beads/issues.jsonl .beads/interactions.jsonl
```

Only run the Dolt commit and push commands when issue changes are pending.
`.beads/issues.jsonl` is a guarded interoperability snapshot; it is not a full
backup of Dolt history or working-set state. The helper refuses to remove
existing issue IDs, dependency edges, or comments and replaces the snapshot
atomically.

The versioned hooks in `.beads-hooks/` are generated by
`bd hooks install --shared`. They delegate to `bd hooks run` and allow ordinary
non-Beads commits without invoking removed legacy commands.
